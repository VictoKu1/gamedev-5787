פרופ' אראל סגל-הלוי

למה ניהול גרסאות?

  • חזרה בזמן: ניסיתם משהו חדש והמשחק נשבר? חוזרים לגרסה האחרונה שעבדה.
    כמו מסע בזמן, בלי הפרדוקסים.
  • עבודה בצוות: כמה אנשים עובדים על אותו פרויקט, והשינויים של כולם מתמזגים לגרסה אחת.
  • ניסויים בלי סיכון: פותחים ענף (branch), מנסים כיוון חדש, ואם לא הצליח - חוזרים לענף הראשי.
  • תיק עבודות: המאגר בגיטהאב הוא מה שמגייסים רואים.

גיט או גיטהאב?

Git GitHub
תוכנה שרצה במחשב שלכם. אתר שמאחסן את המאגרים ברשת.
שומרת את ההיסטוריה של הפרויקט. מסנכרן בין חברי הצוות.
עובדת גם בלי אינטרנט. ארגונים, סקירת קוד, דף רידמי, אירוח המשחק.

לא אוהבים שורת פקודה? GitHub Desktop עושה את אותו הדבר עם כפתורים.

מושגים בסיסיים

repository מאגר: תיקיית הפרויקט עם כל ההיסטוריה שלה.
commit נקודת שמירה: תמונת מצב של הפרויקט + הודעה שמסבירה מה השתנה.
push / pull דחיפה / משיכה: שליחת קומיטים לגיטהאב / קבלת הקומיטים של אחרים.
branch ענף: קו פיתוח נפרד, שלא מפריע לענף הראשי.
merge מיזוג: איחוד השינויים מענף אחד לענף אחר.

מחזור העבודה היומי


git clone https://github.com/my-team/my-game.git   # פעם אחת

git pull                          # 1. מקבלים את השינויים של הצוות
                                  # 2. עובדים ביוניטי...
git status                        # 3. מה השתנה?
git add .
git commit -m "Add enemy chase"   # 4. נקודת שמירה
git push                          # 5. משתפים עם הצוות

קומיטים קטנים ותכופים, עם הודעה שמסבירה מה השתנה.

"fix", "update", "asdf" - לא.
"Fix coins not collected after restart" - כן.

ענפים

  1. הענף הראשי (main) תמיד עובד.
  2. כל רכיב חדש - בענף משלו: git switch -c enemy-ai
  3. כשהוא מוכן: Pull Request בגיטהאב.
  4. חבר צוות קורא את הקוד, מעיר, מאשר - ורק אז מיזוג.

ארגון בגיטהאב

חשבון-צוות (Organization) - למה?

  • לכל חברי הצוות יש גישה לכל המשחקים, וכולם מקבלים הכרה על העבודה.
  • משחקי יוניטי גדולים מאד - חשבון פרטי עלול להיחסם.
    ולכן כדאי לפתוח ארגון גם אם אתם עובדים לבד.

לא צריך חשבון חדש וסיסמה חדשה - מספיק שאחד מחברי הצוות יפתח ארגון ויזמין את השאר.

איך פותחים ארגון?

  1. סימן + למעלה מימין ← New organization.
  2. שם מקורי לצוות, למשל ראשי התיבות של השמות שלכם. (אין רעיון? שאלו בינה מלאכותית.)
  3. People ← Invite: מזמינים את כל חברי הצוות.
  4. מסמנים את החברות בארגון כציבורית (הסבר).
  5. כל מאגר חדש של הצוות - משייכים לארגון.
    שייכתם בטעות לחשבון הפרטי? Settings → Transfer ownership.

גיט ויוניטי

  • לא מעלים הכול! התיקיות Library, Temp, Logs, obj, Builds נוצרות מחדש אוטומטית, והן ענקיות.
    כשיוצרים מאגר, בוחרים Add .gitignore → Unity (התבנית).
  • קבצי .meta - כן מעלים! בלעדיהם כל הקישורים בסצנה נשברים.
  • קבצים גדולים: גיטהאב חוסם קובץ מעל 100MB. לסרטונים ולמודלים כבדים יש Git LFS.

התנגשויות

שניים שינו את אותו קובץ באותו מקום? גיט לא יודע מה לבחור:


<<<<<<< HEAD
    speed = 8f;
=======
    speed = 5f;
>>>>>>> enemy-ai
  • בקוד: מחליטים, מוחקים את הסימנים, קומיט.
  • בסצנות ובפריפאבים - כמעט בלתי אפשרי לפתור ידנית. ולכן כל אחד עובד בסצנה או בפריפאב משלו.
  • git pull לפני שמתחילים לעבוד - חוסך הרבה התנגשויות.

גיט וסוכנים

  1. לפני שנותנים לסוכן לשנות משהו - קומיט.
  2. אחרי - קוראים מה הוא שינה: git diff (או בלשונית Changes ב-GitHub Desktop).
  3. לא אהבתם? חוזרים לקומיט האחרון: git restore .
    זהירות - מוחק את כל השינויים שלא נשמרו בקומיט.
  4. אהבתם? קומיט עם הודעה שאתם כתבתם, וקראתם.
  5. לעולם לא מעלים מפתחות (API keys) או סיסמאות למאגר.

קובץ רידמי

README.md - הדבר הראשון שרואים כשנכנסים למאגר. חלון הראווה שלכם.

  • מה המשחק ואיך משחקים בו.
  • קישור למשחק - אחרי שתעלו אותו לרשת.
  • צילומי מסך וסרטון הדגמה (למשל עם ScreenToGif).
  • הסבר על הקוד: אילו רכיבים יצרתם ואיך, עם קישורים לשורות הקוד.
  • קרדיטים: תמונות, צלילים, נכסים, מדריכים - וכלי בינה מלאכותית.
    הכירו טובה לכל מי שעזר לכם.

פרסום ברשת

GitHub Pages מארח את המשחק בחינם:

  1. ביוניטי: File → Build Profiles → Web.
  2. Player Settings → Publishing Settings: מסמנים Decompression Fallback.
    בלי זה המשחק לא נטען בגיטהאב.
  3. בונים לתיקייה docs במאגר, קומיט ו-push.
  4. בגיטהאב: Settings → Pages, בוחרים את הענף ואת התיקייה /docs.
  5. אחרי דקה-שתיים: https://my-team.github.io/my-game

עכשיו תורכם..

  1. פתחו ארגון לצוות והזמינו את כל החברים.
  2. צרו מאגר בארגון, עם .gitignore של יוניטי.
  3. שבטו אותו למחשב, וצרו בתוכו פרויקט יוניטי.
  4. קומיט ראשון, push - ובדקו בגיטהאב שאין תיקיית Library.
  5. כל אחד מחברי הצוות: ענף, שינוי קטן, Pull Request - והשני מאשר.
  6. כתבו רידמי עם שם המשחק ושמות חברי הצוות.
